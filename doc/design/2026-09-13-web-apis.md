# Web 平台 API（WinterTC 子集）设计与实现记录

日期：2026-09-13（实现完成 2026-09-16；2026-09-17 改为模块制，见第 2 节）
范围：定时器与核心原语、纯计算标准库、网络能力（`fetch`）。
面向用户的说明见 `doc/wiki/api/web-apis.md`。

## 1. 目标与非目标

目标：

- 让面向 Web / Workers 编写的常见脚本（定时器、编码、URL、事件、Streams、`fetch`）无需自带 polyfill 即可运行。
- 语义尽量贴近 WHATWG / WinterTC 规范，偏差逐项列出（第 6 节）。
- 默认安全：网络能力必须显式开启并可限制。
- 与引擎池、`softReset`、`reinitialize` 生命周期一致，不引入跨租户残留和引用泄漏。

非目标：

- 不宣称 WinterTC 合规。QuickJS 没有 `WebAssembly`，而它是最小公共 API 的必需项。
- 不引入 `quickjs-libc`（`std` / `os`）。
- 不提供 DOM、`XMLHttpRequest`、`WebSocket`、Cookie 存储。

## 2. 模块与能力

**本节在 2026-09-17 重写。** 初版按 L0 / L1 / L2 分级发布，那是个错误的模型，理由记在下面，
因为它解释了现在这套设计为什么长这样。

### 2.1 为什么不是分级

分级把三件正交的事压成了一个序数：

1. **依赖序**——机械的，应该被算出来，不该出现在用户面前；
2. **能力 / 权限**——安全相关，必须显式；
3. **每 context 成本**——是文档事实，不是一个轴。

后果有三个，都是实打实的：

- "L1" 里藏着一条 4 层深的依赖链（`encoding` / `url` → `streams` → `blob` → `http`）。
  把它们叫做同一层是**事实性的误标**，不只是粒度粗。
- "L2 隐含开启 L1" 是跨级依赖。一个层与层之间互相依赖的体系不是层级，是一个被贴了层号的拓扑序。
- 归类被掩盖的错误没人发现：`navigator` 一直安装在 `crypto` 模块里，因为它们同属 "L1"。

依赖不会消失，问题在于依赖被暴露成了用户需要理解的概念。

### 2.2 现在的模型

`lib/web/src/js_*.dart` 本来就是一张模块图——`internal` 对象上的读写关系就是边。现在把这张图
声明出来（`JsWebModule`），由安装器求**依赖闭包**并拓扑排序。用户面前只剩两个真实概念：
**要哪些模块**、**哪些模块需要授权**。

| 模块 | 依赖 | 自身开销 |
|---|---|---|
| `core` | — | 82 KiB |
| `events` | `core` | 30 KiB |
| `encoding` | `core` | 7 KiB |
| `url` | `core` | 64 KiB |
| `crypto` | `core` | 22 KiB |
| `navigator` | `core` | 3 KiB |
| `streams` | `core`, `events`, `encoding` | 89 KiB |
| `blob` | `core`, `streams` | 23 KiB |
| `http` | `core`, `url`, `events`, `streams`, `blob` | 51 KiB |
| `fetch` | `core`, `http`, `streams` | 8 KiB |

预设：`JsWebApis.none()`（什么都不装）、`JsWebApis()`（只装 `core`，默认）、
`JsWebApis.standard()`（全部纯计算模块）、`JsWebApis.standard(fetch: ...)`。
`JsWebApis(modules: {...})` 直接点名。

"`fetch` 隐含 L1" 那个特例分支消失了——它现在是闭包计算的普通结果。注意闭包比旧的
`installsWeb` 更精确：`JsWebApis(fetch: ...)` 不再顺带安装 `crypto` 和 `navigator`，
因为 `fetch` 并不需要它们。

### 2.3 能力轴

`fetch` 是唯一伸到 JS context 外面的模块，所以它是唯一不能被单独打开的：只有在传入授予它的
策略对象（`JsFetchOptions`）时才会安装，否则 `JsWebModule.fetch` 出现在 `modules` 里会抛
`ArgumentError`。这就是分级方案缺的那个依据——不是"L2 比较高级"，而是**这个模块需要宿主权限，
所以它必须携带一份权限声明**。其余模块全部是对堆内已有值的纯计算。

### 2.4 粒度为什么停在这里

模块原子就是现在的 9 个（+`fetch`）源文件，不再细分：`http` 有 663 行，但 `Headers` /
`Request` / `Response` 互相引用，是一个规范单元；`streams` 的规范算法同样互相调用。
换句话说，**文件切分本来就是对的，错的只是把它们打包成 L1 这个动作**。

### 2.5 为什么不做编译期裁剪

曾考虑 OpenWrt 式的编译期选择，结论是这个仓库里没有杠杆：

- C 侧只有 `jsNewWebNatives` 四个函数（约 150 行），5622 行 Web API 里其余全是 Dart + JS，
  能裁掉的原生体积接近于零；
- 真正的成本（每 context 160 / 451 KiB 的 JS 堆、0.9 / 2.3 ms 的安装时间）是**运行期**
  决定的，因为模块字节码是 per-context 求值的；
- 交付层面也没有通道：Flutter 插件的消费者没有 configure 步骤能把 `-D` 传进插件自己的
  CMakeLists / podspec / gradle，Dart 也没有针对库代码的条件编译。

唯一真实的"编译期"收益是 AOT tree-shaking：模块源码是 `const String`，`_install` 不再无条件
引用全部常量之后，没被选中的模块源码可以被摇掉。这个收益来自显式模块选择本身，不需要 menuconfig。

## 3. 代码结构与层次

```
cxx/ffi.cpp              jsNewWebNatives：UTF-8 编解码、单调时钟；jsSetStripInfo / jsGetStripInfo
lib/quickjs/             引擎绑定层：新增 natives 与 strip 的 FFI 绑定、createWebNatives、compile(stripSource:)
lib/web/web_apis.dart    宿主 API 层（library）：JsWebModule 注册表与闭包求解、JsWebApis / JsFetchOptions / …
  src/host.dart          安装流程、字节码缓存、定时器 / console / 随机数 / 摘要宿主
  src/fetch_host.dart    fetch 宿主、重定向与策略、默认 HttpClient 处理器
  src/sha.dart           SHA-1/256/384/512 与 HMAC（纯 Dart）
  src/js_core.dart       core
  src/js_events.dart     src/js_encoding.dart  src/js_url.dart  src/js_streams.dart
  src/js_blob.dart       src/js_http.dart      src/js_crypto.dart
  src/js_navigator.dart  src/js_fetch.dart（能力模块）
lib/javascript_runtime.dart  init() 调用安装器；releaseHostCaches() 调用 dispose
```

- 引擎绑定层只暴露能力，不含 Web 语义。
- 宿主 API 层只通过 `JavascriptRuntime` 的公开接口（`compile` / `evaluateBytecode` / `JSInvokable.invoke` / `executePendingJobs`）工作。
- `init()` 只负责编排，不再内联 JS 字符串。

### 3.1 JS 模块协议

每个模块是一段脚本，完成值是函数。`core` 是 `(natives, host) => { fire, install }`；其余模块经由
`install(moduleFn, moduleHost)` 调用，签名为 `(host, internal, natives) => exports`：

- `natives`：C 函数对象。
- `host`：本模块用到的 Dart 函数。
- `internal`：模块间共享的私有对象（`DOMException`、品牌检查、body 工具、流内部算法等），不暴露到全局。
- `exports`：Dart 需要回调的 JS 函数（定时器 `fire`、fetch 的 `onResponse` / `onChunk` / `onEnd` / `onError`）。

Dart 侧持有 `exports` 中的函数引用，`dispose` 时释放。全局属性一律以不可枚举、可写、可配置的方式定义
（与浏览器一致），不再使用 `var` 绑定或 `__NATIVE_FLUTTER_JS__*` 之类可篡改的全局变量。

### 3.2 字节码缓存

模块源码在进程内首次安装时编译为字节码并按模块名缓存，之后每个引擎、每次 `softReset` /
`reinitialize` 都走 `evaluateBytecode`。两个细节：

- 编译在**一个临时引擎**里进行（`JsWebApis.none()`、`memoryLimit: 0`），这样解析峰值不会算在
  目标运行时的 `memoryLimit` 上。
- 编译时打开 `JS_STRIP_SOURCE`（新增公开参数 `compile(..., stripSource: true)`），保留行号用于堆栈，
  但不保留函数源码，省下约 28 KiB/上下文。

不随包分发字节码：它与 QuickJS 版本强绑定。

### 3.3 事件循环

- 宿主回调（定时器触发、fetch 数据到达）视为一个宏任务：先 `invoke`，再 `executePendingJobs()`，
  与浏览器"任务后微任务检查点"一致。
- `QuickJsRuntime2.autoExecutePendingJobs == false` 时同样不自动排空，保持用户的显式控制。
- 每次回调单独受 `timeout` 约束；回调中抛出的异常经 `reportError` 记录，不再被静默吞掉。

### 3.4 生命周期

`releaseHostCaches()`（由 `close` / `softReset` / `reinitialize` 调用）会取消所有 Dart `Timer`、
中止进行中的 fetch 并关闭自有 `HttpClient`、释放持有的 JS 函数引用。宿主对象带 `disposed` 标记，
异步到达的事件在释放后直接丢弃。

## 4. 关键实现决策

| API | 实现位置 | 原因 |
|---|---|---|
| 定时器 | Dart `Timer` + JS 回调表 | 真正取消；支持 interval 与额外参数；无 JSON 往返 |
| `console` | JS 格式化 + 一个 Dart 函数 | 支持 `%s %d %o`、BigInt、循环引用、Error 堆栈；不走 `JSON.stringify` |
| `structuredClone` | JS | QuickJS 的 `JS_WriteObject` 不支持 Map / Set / RegExp / Error |
| `TextEncoder` / `TextDecoder` | C natives | 直接 UTF-8 ↔ JSString；按 WHATWG 规则替换孤立代理项与非法序列 |
| `performance.now` | C natives（`steady_clock`） | 高精度、无桥接开销 |
| 随机数 | Dart `Random.secure()` | 跨平台安全随机源，无需每个平台的 C 实现 |
| SHA / HMAC | Dart（自实现） | 不新增 pub 依赖；不增加 4 份 native 副本的体积 |
| URL | JS（WHATWG 状态机） | 语义贴近规范；Dart `Uri` 是 RFC 3986，行为不同 |
| Streams | JS（规范算法移植） | 需要与 Promise 微任务严格配合 |
| `fetch` | JS 类型 + Dart 处理器 | 网络由 `HttpClient` 完成；响应体按拉取逐块传入，形成背压 |

重定向与 `allowUrl` 由**运行时**处理而不是 handler：每一跳都要过策略，避免通过重定向绕过白名单。

## 5. 公开 API

```dart
final js = QuickJsRuntime2(
  webApis: JsWebApis.standard(
    fetch: JsFetchOptions(
      allowUrl: (uri) => uri.host == 'api.example.com',
      maxResponseBytes: 16 * 1024 * 1024,
    ),
  ),
);

// 只要 URL 解析：224 KiB 而不是 459 KiB。
final small = QuickJsRuntime2(
  webApis: const JsWebApis(modules: {JsWebModule.url}),
);
```

`getJavascriptRuntime(webApis: ...)` 和 `JsEnginePoolConfig(webApis: ...)` 透传该配置。
`JsWebApis.resolvedModules` 给出排好序的闭包，`installs(module)` 回答某个模块是否在其中。
`JsFetchOptions.handler` 可替换网络实现（接入应用自己的 HTTP 栈或测试桩）。

## 6. 已知偏差与未实现

- **URL**：不做完整 IDNA / UTS #46 映射；非 ASCII 域名走 NFC + 小写 + Punycode。
- **Streams**：不支持字节流（`type: 'bytes'`）与 BYOB reader，调用抛 `TypeError`；pull 的调度可能与
  其它引擎差一个微任务（测试断言不变量而不是精确序列）。
- **`TextDecoder`**：只支持 UTF-8，其它标签抛 `RangeError`。
- **`crypto.subtle`**：只有 `digest` 与 HMAC，其余返回 `NotSupportedError`。
- **`fetch`**：仅 `http:` / `https:`；`ReadableStream` 请求体先读完再发送；无 Cookie、CORS、缓存；
  `redirect: 'manual'` 返回真实 3xx 响应。
- **未实现**：`WebAssembly`、`CompressionStream` / `DecompressionStream`、`URLPattern`。
- **`IsolateQjs`**：只安装 `core`。

与 Node.js 24 的差分测试中，有三处是 **Node 偏离规范、本实现遵循规范**，测试里单独标注：
`File.webkitRelativePath` 存在、`endings: 'native'` 也转换单独的 CR、`FormData` 可被
`structuredClone` 克隆。

## 7. 行为变化

- 公开配置从分级（`core:` / `web:` 布尔）改为模块集合：`JsWebApis(core: false)` →
  `JsWebApis.none()`，`JsWebApis(web: true)` → `JsWebApis.standard()`，
  `JsWebApis(fetch: ...)` 保持可用但闭包更精确（不再顺带装 `crypto` / `navigator`；
  要旧的全集用 `JsWebApis.standard(fetch: ...)`）。Web API 尚未随版本发布，未保留过渡期。
- `navigator` 从 `crypto` 模块移到自己的 `navigator` 模块（旧分级下的错误归类）。
- 在 `modules` 里写 `JsWebModule.fetch` 而不给 `JsFetchOptions` 会抛 `ArgumentError`。
- 移除 `ConsoleLog` / `SetTimeout` 两个内部通道与 `__NATIVE_FLUTTER_JS__*` 全局变量。
- `clearTimeout` / `clearInterval` 现在真正取消 Dart `Timer`；回调异常改为经 `reportError` 记录。
- `console` / 定时器等全局属性变为不可枚举。
- 安装 `core` 需要约 320 KiB 的 `memoryLimit`（`standard()` 约 1 MiB）。低于此值的引擎应使用
  `JsWebApis.none()`；`example/test/boundary_test.dart` 的边界用例已按此调整。
- 顺带修复 JS→Dart 字符串丢失开头 BOM 的问题（`Utf8Decoder` 会静默吞掉 U+FEFF）。
- 新增公开参数 `JavascriptRuntime.compile(..., stripSource: false)`。
- 移除未被使用且依赖不存在的 `XMLHttpRequest` 的 `assets/js/fetch.js`（同时删掉 `pubspec.yaml` 的
  资产声明）；example 的 Fetch 按钮改为开启 `JsFetchOptions` 后真正可用。

## 10. 后续修正（2026-09-18）：可选依赖与"功能划分"

- **模块是功能划分，不是权限划分。** 第 2、3 节把 `fetch` 描述为"唯一携带能力/权限的模块"、
  其余模块"对堆内已有值的纯计算"，这个说法不准确：`core` 会调度 Dart 定时器、写日志、
  读系统随机源，`navigator` 暴露宿主配置的 userAgent。选择模块只决定 API 是否存在及其开销，
  不构成沙箱；真正的边界是宿主传入的对象（`JsFetchOptions.allowUrl` 等）和
  `memoryLimit` / `timeout`。`JsWebModule.capability` 因此改名为 `hostConfig`
  （值为 `'JsFetchOptions'`），语义是"安装它必须提供的宿主配置对象"。
- **可选依赖。** `JsWebModule.optional` 中的模块不会被自动拉入；若同时安装，
  解析器保证它排在前面，模块再通过 core 的 `has(name)` 打开对应功能：

  | 模块 | 必需 | 可选 → 功能 |
  |---|---|---|
  | `streams` | `core`, `events` | `encoding` → `TextEncoderStream` / `TextDecoderStream` |
  | `blob` | `core` | `streams` → `Blob.prototype.stream()` |
  | `http` | `core`, `url`, `events`, `streams` | `blob` → `blob()` / `formData()`、Blob/FormData 请求体 |
  | `fetch` | `core`, `http`, `events`, `streams` | — |

  `streams → events` 保持必需（`WritableStreamDefaultController.signal` 与 `pipeTo` 的
  `signal` 是规范要求）；`fetch` 补上了此前只经 `http` 间接获得的 `events`。
- **下沉到 core 的只有默认判定和查询：** `isAbortSignal` / `isBlob` / `isFormData`
  默认返回 `false`（对应模块未安装时此类对象不可能存在），由 `events` / `blob` 覆盖；
  `has(name)` 查询模块是否已安装。实际功能不下沉。
- **约定与检查：** 模块只在开头用一次 `const {...} = internal;` 读取，只用
  `Object.assign(internal, {...})` 写入；`example/test/web_apis_internal_names_test.dart`
  静态检查读取的名字都来自已声明的依赖、可选依赖的名字有 `has()` 保护、导出不重名。
- **行为变化：** 单独安装 `{http}`、`{blob}`、`{streams}` 或只传 `fetch:` 时，得到的全局
  比以前少（见 CHANGELOG）。`standard()` 不受影响。
